# МАС для управления режимом производства товарного ДТ

Хакатон Нефтекод. Цепочка **АВТ → гидроочистка (24-2000) → блендинг**.

Система получает состояние процесса, оценивает последствия возможных действий
и формирует безопасную, объяснимую рекомендацию оператору. Либо корректно
отказывается её давать.

## Быстрый старт

```bash
pip install -r requirements.txt
python run.py demo
```

На macOS LightGBM дополнительно требует системную библиотеку OpenMP,
иначе `import lightgbm` падает с `Library not loaded: @rpath/libomp.dylib`
и не запускается вообще ничего:

```bash
brew install libomp
```

С флагом `--telemetry` дополнительно подгружаются исторические ряды из
`data/` (около 13 секунд). Без них агент надёжности считает два фактора
из пяти: нестабильность и тепловое напряжение требуют скользящего окна,
а в снимке `ProcessState` истории нет.

Ожидаемый результат — три сценария из раздела 6 ТЗ:

| Сценарий | Ожидаемое поведение | Статус |
|---|---|---|
| `normal` | лишних управляющих действий нет | без изменений, запас 0.88 мг/кг |
| `quality_risk` | корректирующее действие, спека выполняется | T5 +2.50, запас 0.26, выпуск не теряем |
| `degraded_data` | отказ от рекомендации с объяснением | REFUSE |

## Архитектура

Пять слоёв. **Два из них не содержат ни моделей, ни LLM** — это архитектурное
свойство, а не экономия.

```
  ┌────────────────────────────────────────────────────────────┐
  │ L0  StateBuilder            ЧИСТЫЙ КОД                     │
  │     as-of join по времени, возраст анализов, dq_flags       │
  │     → ProcessState                                         │
  └────────────────────────────────────────────────────────────┘
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
  ┌───────────────┐     ┌──────────────────┐
  │ L1a  Качество │     │ L1b  Надёжность  │
  │ ML + интервал │     │ прокси-severity  │
  │ →QualityAssess│     │ →ReliabilityAssess
  └───────────────┘     └──────────────────┘
        │                       │ allowed_ranges
        └───────────┬───────────┘
                    ▼
  ┌────────────────────────────────────────────────────────────┐
  │ L2  Оптимизация                                            │
  │     кандидаты внутри trust region → list[Candidate]        │
  └────────────────────────────────────────────────────────────┘
                    ▼
  ┌────────────────────────────────────────────────────────────┐
  │ L3  ConstraintGate          ЧИСТЫЙ КОД, БЕЗ LLM            │
  │     сравнение чисел с config/constraints.yaml              │
  │     → list[GateVerdict]                                    │
  └────────────────────────────────────────────────────────────┘
                    ▼
  ┌────────────────────────────────────────────────────────────┐
  │ L4  Orchestrator                                           │
  │     лексикографический выбор, объяснение, JSON-трейс       │
  │     → Recommendation | REFUSE                              │
  └────────────────────────────────────────────────────────────┘
```

### Уровень серы даёт измерение, модель даёт эффект действия

Абсолютный прогноз серы честен, но его conformal-интервал шириной 6.3 мг/кг
при лимите 10 не проходит жёсткую проверку по `hi` никогда, включая вариант
«ничего не менять». Поэтому уровень берётся из измерения (ПАК каждые
10 минут, ЛИМС несколько раз в сутки), а модель отвечает только за разницу
между текущим и предлагаемым режимом. Это стандартный bias update
инференциального управления, а не ослабление проверки.

Ширина интервала: эмпирический q90 роста серы за время с момента анализа
(по 175 тыс. точек ПАК, таблица в `config/constraints.yaml`), плюс
расхождение ЛИМС и ПАК, плюс половина предсказанного эффекта как
неопределённость модели. Реализация — `agents/quality.py._sulfur_anchored()`.

### Режим восстановления

Если продукт УЖЕ вне спецификации, Gate отбраковывает все варианты, и
формально система должна отказаться. Но тогда она молчит ровно тогда,
когда нужна. Оркестратор в этом случае выбирает вариант, который улучшает
запас по сере и не нарушает больше ничего, и прямо пишет в отчёте, что
спецификация за один шаг не восстанавливается (`orchestrator._recovery()`).
Нарушение не прячется: оно уходит в `Recommendation.checks_failed` и
печатается как `[!] НАРУШЕНО`.

### Языковая модель объясняет решение, но не принимает его

```bash
echo "GEMINI_API_KEY=ваш-ключ" > .env        # .env в .gitignore
python run.py ask --scenario quality_risk "почему не подняли температуру сильнее?"
```

Отчёт оператору собирается кодом и самодостаточен. Модель нужна для
другого: отвечать на вопросы, которых в шаблоне нет — «почему отклонён
вариант с большим выпуском», «что будет, если ничего не делать». Ответы
уже лежат в трейсе (1089 кандидатов с вердиктами и запасами), но читать
JSON оператор не станет.

Три ограничения, которые делают это безопасным:

1. **Модель не участвует в решении.** Числа, отбраковку и выбор варианта
   считает код. Без ключа и без сети система выдаёт те же рекомендации,
   а `ask` отвечает шаблоном по тем же числам (`config/llm.yaml`,
   `enabled: false` выключает обращения к модели полностью).
2. **Каждое число проверяется.** Числа из ответа сверяются с данными
   решения; не найденное помечается как неподтверждённое, а при
   `strict: true` такой ответ не показывается вовсе. Тот же принцип, что
   у Gate: убедительность текста не даёт никаких прав.
3. **Контекст — только факты решения.** В модель уходит сжатый трейс:
   состояние, оценки агентов, рекомендация, проверки и статистика
   отбраковки. Своих источников у неё нет.

### Три принципа, на которых всё держится

**1. Propose-and-verify.** Агенты предлагают, `gate.py` проверяет.
Модуль Gate не импортирует ничего из `agents/` и не вызывает LLM.
Ни один вариант не может пройти за счёт убедительного объяснения.

**2. Жёсткие ограничения проверяются по консервативной границе интервала.**
Для серы это `hi`, не `mean`. Прогноз 9.6 при лимите 10 выглядит безопасно,
но с интервалом ±0.8 верхняя граница 10.4 означает реальный риск.
На это есть отдельный тест: `test_sulfur_checked_on_upper_bound_not_mean`.

**3. Минимальное воздействие.** Если запас по ограничению уже достаточен,
система ничего не трогает. Без этого правила оптимизатор всегда уходит
в максимальную severity ради лишнего запаса.

### Разрешение конфликта целей

Лексикографический порядок, не взвешенная сумма:

1. жёсткие ограничения (бинарно, решает Gate)
2. достаточен ли запас по качеству
3. величина воздействия (меньше = лучше)
4. тяжесть режима
5. экономика

Экономика последняя сознательно. Ключевой принцип ТЗ: недопустимый режим
нельзя компенсировать производительностью или затратами.

## Распределение работ

| Кто | Классы и файлы | Что доделать |
|---|---|---|
| Person 1 — Lead / Архитектор | `contracts.py`, `gate.py`, `orchestrator.py`, `explain.py`, `tracing.py`, `agents/quality.py` | оболочка готова, дальше калибровка порогов, демо, интеграционные тесты |
| Person 2 — Data Engineer | `data/loaders.py`, `data/state_builder.py`, `data/tags.py`, `config/tags.yaml`, `agents/reliability.py` | `load_lims`, `load_pak`, `build_state`, затем `_severity` и `allowed_ranges` |
| Person 3 — ML Engineer | `models/avt.py`, `models/go.py`, `models/features.py` | ВАК-формулы, LightGBM с monotone_constraints, интервалы, сплит по времени |
| Person 4 — AI / Optimization | `agents/optimizer.py`, `config/constraints.yaml` | целевая функция, калибровка `cost_proxy`, подключить `pareto_front()`, диапазоны и пороги |

### Граница между `models/` и `agents/quality.py`

Это единственное место, где двое могли бы столкнуться в одном файле,
поэтому разделено явно:

- `models/` — чистые предсказатели. Принимают плоский словарь признаков,
  возвращают `dict[str, Interval]`. Не знают про `ProcessState`,
  спецификации, возраст анализов и `confidence`. Пишет Person 3.
- `agents/quality.py` — оболочка. Вызывает обе модели, сцепляет цепочку
  АВТ → ГО, считает `confidence` и `spec_risk_prob`, собирает
  `QualityAssess`. Пишет Person 1.

Подмена заглушки на обученную модель делается одной строкой и не
затрагивает ни один другой слой:

```python
QualityAgent(avt_model=MyAVTModel.load("..."), go_model=MyGOModel.load("..."))
```

### Правило для `contracts.py`

Файл не принадлежит никому единолично. Новое поле — сначала сообщение
команде и `SCHEMA_VERSION` вверх, потом правка. Логики в этом файле нет
и быть не должно.

Каждый `TODO` в коде подписан ответственным. Заглушки возвращают
осмысленные значения, поэтому полный цикл работает уже сейчас
и никто никого не ждёт.

## Найдено в данных при разведке

Эти факты влияют на код, поэтому зафиксированы здесь.

**Сера работает вплотную к лимиту.** ПАК `24-2000:Mg.Sulfur`, 189 649 точек,
10-минутный шаг, 01.01.2023 → 10.08.2026. Медиана 8.37 мг/кг при лимите 10.
**12.05 % времени показания выше 10.** По годам: 11.5 / 16.1 / 6.9 / 14.8 %.
Ценность системы измеряется сокращением доли времени вне спецификации,
а не средним снижением серы.

**Отказы ПАК видны напрямую.** Временных пропусков нет, но есть залипания:
67 эпизодов дольше часа, максимальный **6731 точка = 1122 ч ≈ 47 суток**
замороженного значения. Реализовано в `detect_stuck()`. Это готовый
демо-сценарий, выдумывать ничего не нужно.

**ПАК `24-2000:D15` начинается только с 05.03.2025.** Модели, использующие
его, теряют две трети истории.

**Готовых ВАК-формул на серу нет ни одной.** Лист ВАК даёт T90 / T50 / I250 /
D15 / CloudPoint / T95 / CFPP для гидроочищенного ДТ и показатели фракций АВТ.
Сера — единственный жёсткий показатель, и его надо моделировать самим.

**Сера линейно из телеметрии не видна.** Максимальная корреляция любой из
26 колонок 24-2000 с ПАК-серой 0.23 по модулю, с лабораторной 0.19.
Для сравнения: вспышка 0.62, плотность 0.53. Нужны лаги и нелинейность.

**Справочник КИП по 24-2000, похоже, сбит.** `242000:T18` подписан как
«давление на выходе К-201», но значения 50…100 с медианой 68.7 и корреляция
0.62 с лабораторной FlashPoint (медиана 68). Спорные коды помечены
`verified: false` в `config/tags.yaml`. Уточнить у организаторов.

**Маркеры-заглушки в данных.** У восьми колонок 24-2000 максимум ровно 307.00,
у трёх ровно 10.00; расходы уходят в минус (`F26` до −23.75). Обрабатывается
в `_clean_sentinels()`.

**Часть ВАК-формул содержит члены `LIMS:...`.** Использовать их как прогноз
и валидировать по тому же ЛИМС — утечка из будущего.

## Допущения

Все помечены в коде и конфигах полем `source: assumption`.

- Жёсткая проверка из ТЗ только одна: сера ≤ 10 мг/кг. Пороги по вспышке,
  CFPP и плотности — **наши модельные допущения**, не промышленные пределы,
  поэтому Gate по ним не отбраковывает: отклонение уходит в
  `GateVerdict.warnings` и печатается оператору как `[~] ВНИМАНИЕ
  (модельное допущение)`. Отбраковывать вариант по придуманной нами
  границе значило бы молча сузить рабочую область установки — лимит ПТФ
  0 °C для летнего сорта зарезал бы любой зимний режим. Диапазоны
  управляемых переменных и размер шага при этом остаются жёсткими:
  ТЗ отдельным пунктом требует не выходить за заданные модельные
  ограничения, а шаг — это trust region модели.
- Диапазоны управляемых переменных — модельные, заданы консервативно
  по истории. Исторический min/max не выдаётся за промышленный предел.
- Дата начала цикла катализатора неизвестна, принята 2023-01-01.
- WABT считается как `Tвх + 2/3·(Tвых − Tвх)`, стандартная отраслевая формула
  для адиабатического реактора.
- `cost_proxy` — прозрачный стоимостной прокси в условных единицах,
  фактических экономических данных в пакете нет.

## Валидация

Сплит строго по времени, случайное перемешивание запрещено:
train до 2025-12-31, test 2026 год. Проверяется на отложенном периоде.

Каждый прогон пишет `artifacts/traces/<ts решения>_<сценарий>_<ts записи>.json`:
вход, оценки агентов, все кандидаты, вердикты Gate, финал и блок `meta` —
коммит, идентификаторы моделей, контрольные суммы всех конфигов и версии
библиотек. Без `meta` через неделю нельзя сказать, почему тот же вход дал
другое число: поменялся код, конфиг или артефакт модели.

Отчёт воспроизводится из файла, ничего не пересчитывая:

```bash
python run.py replay artifacts/traces/20260314T0820_quality_risk_*.json
```

По умолчанию трейс компактный (806 КБ против 2.2 МБ): список выполненных
проверок хранится один раз на цикл, а не копией у каждого из 1089
кандидатов, числа округляются до четырёх знаков. Сами кандидаты и их
запасы сохраняются полностью — без них трейс перестал бы доказывать,
почему вариант отброшен. Полный дамп с отступами: `save_trace(..., full=True)`.

## Куда расти

- `pydantic` вместо dataclasses, если нужна валидация типов на рантайме
  (поля не меняются, замена механическая)
- conformal prediction вместо эвристического интервала в `QualityAgent`
- Парето-фронт: `OptimizerAgent.pareto_front()` написан, но его ключ
  `(cost_proxy, severity_delta, sulfur_hi)` не учитывает выпуск, а затраты
  и тяжесть режима обе зависят только от `242000:T5`. Фронт из-за этого
  вырождается: точки с одинаковой температурой неразличимы. Пока в
  альтернативах показываются крайние точки компромисса по каждому
  критерию (`orchestrator._alternatives()`); добавить `yield_delta`
  в ключ фронта — задача Person 4
- LLM поверх `Recommendation` для пересказа человеческим языком.
  Права менять числа у него нет: он получает готовую структуру.
